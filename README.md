# Postura ── 姿勢を、数字で診る。

整骨院・整体院向けの簡易姿勢分析Webアプリ。患者の前後左右の写真から骨格を自動検出し、左右差や前後傾を数値化、**ルールベース（AI不使用）** で所見コメント・推奨筋肉・トレーニングメニューを自動生成します。

所見文の生成ルールは [`DIAGNOSIS_RULEBOOK.md`](DIAGNOSIS_RULEBOOK.md)、トレーニング処方ルールは [`TRAINING_RULEBOOK.md`](TRAINING_RULEBOOK.md) を参照。

公開URL: <https://tmk4men.github.io/posture-analysis/>

- `/` → ランディングページ（紹介HP）
- `/app.html` → 姿勢分析ツール本体

## 必要なもの

- 最新のブラウザ（Chrome / Edge / Safari の最新版）
- インターネット接続（初回の MediaPipe モデルのダウンロード用のみ）
- **APIキーは不要**。所見文・推奨筋肉・トレーニングはすべて端末内のルールで生成します（外部AIへの送信なし）。

## 使い方

### 1. アプリを起動

このフォルダの `app.html` をブラウザで直接開く（ローカルで紹介ページを見たい場合は `index.html`）。
簡易サーバーを立てる場合は `python3 -m http.server 8000` など。

### 2. 患者情報入力（任意）

- 患者氏名・撮影日・性別・週のトレーニング頻度を入力（すべて端末内のみで保持、サーバ送信なし）
- 気になる不調・痛みの部位を選ぶと、人体図のハイライトと所見文に反映されます

### 3. 写真アップロード

正面・右側面の枠から、撮影した写真をアップロード。
それぞれ自動で骨格線・基準線（青：肩、橙：骨盤）が描画され、計測値が表示されます。

### 4. 解析結果の生成

「解析結果」ボタンで、計測値・申告部位・週頻度から **端末内のルール** で所見文・推奨筋肉・トレーニングメニューを生成します（外部送信なし）。生成ルールは `DIAGNOSIS_RULEBOOK.md` を参照。

### 5. レポート印刷

「レポート印刷」でブラウザ印刷ダイアログが開きます。
A4で2〜3枚に収まるレイアウトで、患者にお渡しできます。

## 撮影のコツ

- 患者から **2〜3メートル離れて、カメラの高さを腰の高さ** に
- 全身（頭〜足首）が画面に収まるように
- 背景はできるだけシンプルに、コントラストを出す
- 服装はシルエットがわかる軽装が望ましい
- 4方向すべて、患者の立ち位置を変えずに自分が回り込んで撮影すると比較しやすい

## 計測している項目

| 視点 | 項目 |
|------|------|
| 正面/背面 | 肩の傾き、骨盤の傾き、頭部の傾き、上半身の左右シフト |
| 左/右側面 | 頭部前方位 (FHP)、肩の前方変位、体幹の前後傾、膝の角度 |

数値はすべて MediaPipe Pose Landmarker（Google製、ブラウザ完結のオンデバイスAI）で検出した33点の骨格座標から計算しています。

## プライバシーとセキュリティ

- 写真・計測値・所見文はすべて **ブラウザ内のみで処理** され、外部への送信は一切ありません（AIも使いません）
- 患者氏名・撮影日・不調部位などの入力も端末内のみで保持し、サーバには送りません
- ネット接続は初回の MediaPipe モデル取得にのみ使用します（以降はキャッシュ）

## カスタマイズ

- **計測項目を増やす**：`src/pose/angles.js` の `computeMetrics` に追加
- **所見文の言い回し・ルール変更**：`src/pose/diagnosis.js`（詳細は `DIAGNOSIS_RULEBOOK.md`）
- **検出感度（しきい値）変更**：`src/pose/thresholds.js`（所見文と筋肉選定に同時反映）
- **印刷レイアウト調整**：`app.css` の `@media print` セクション
- **モデル変更**：`src/pose/detector.js` の `MODEL_URL`（lite / full / heavy の3種類）

## デプロイ時のキャッシュバスター

GitHub Pagesは静的アセットをブラウザに約10分キャッシュさせるため、コード更新後も既訪問ユーザーが古いJS/CSSを使い続けることがあります。これを防ぐため、リリース前に `?v=...` クエリ文字列を更新するスクリプトを用意しています。

```bash
./scripts/bump-cache.sh   # app.html / index.html の ?v= を現在のUTC時刻に更新
git add -A
git commit -m "release: bump assets"
git push
```

仕組み：
- `app.html` のエントリ `src/main.js?v=YYYYMMDD-HHMM` から、`main.js` が自分の `import.meta.url` を読み取り、すべての動的importに同じ `?v=...` を伝播
- 結果、CSSとES Moduleツリー全体が一斉に新しいキャッシュキーになる
- 触らずに `git push` した場合は `?v=` が据え置きなので、ブラウザの最大10分キャッシュに依存
